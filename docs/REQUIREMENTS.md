# Требования к интеллектуальному сервису

Тема: «Автоматизация процессов оценки эффективности работы сотрудника университета с применением интеллектуального анализа данных».

Статус: рабочий черновик от 20 ноября 2026 года. Функции ниже выведены из предоставленных требований к практике; предметные показатели ещё предстоит согласовать.

## Предметные решения и ограничения

- Демонстрационная категория: условные преподаватели; данные симуляционные по решению пользователя.
- Наблюдение: сотрудник × период, два периода на сотрудника, разделение по ID.
- Цель: искусственная категория efficiency_level, связанный score исключён из признаков.
- Выбор классификатора: macro-F1 validation; дополнительно сохраняется Accuracy.
- Реальный источник и валидность эффективности сотрудников не подтверждены; это открытый критерий исходного задания.

## Основной пользовательский сценарий

1. Пользователь указывает ссылку на датасет.
2. Сервис проверяет структуру, показывает состав данных и проблемы качества.
3. Пользователь запускает подготовку данных и обучение базовой и DL-моделей.
4. Сервис показывает графики, метрики на train/validation/test и сравнение экспериментов.
5. Пользователь сохраняет или загружает модель и получает её результаты на новых данных.

## Критерии готовности

- Реальный датасет содержит минимум 1000 строк и 10 колонок, соответствует задаче и доступен по ссылке.
- Подготовка признаков не использует сведения из валидационной и тестовой выборок при обучении.
- Обучение воспроизводимо; параметры, разбиение данных и метрики сохранены.
- Реализованы базовая модель и DL-модель, сравнение и хотя бы одна обоснованная итерация улучшения.
- Сохранённая модель загружается и работает без обязательного повторного обучения.
- Интерфейс позволяет пройти основной сценарий; ошибки входных данных обрабатываются понятными сообщениями.
- Метрики, ограничения и ошибки модели отражены в отчёте. Достигнут требуемый уровень качества либо согласована иная подходящая метрика.
- Есть `main.py`, ноутбук, сохранённые модели, зависимости с версиями и инструкция запуска.
- Проведено тестирование минимум четырьмя методами и проверена установка в чистом окружении.

## Проверенный программный комплект

Основной цикл реализован и пройден настоящим Chrome на1440/390px. main.py без аргументов запускает GUI, файл/HTTP-ссылка принимаются всеми формами, Markdown-пакет и модель скачиваются, прогноз применяется без повторного обучения. Метрики сохранённой симуляции,76тестов, чистая установка и открытые формальные условия перечислены в ACCEPTANCE_MATRIX.md. Реальные данные не заявляются.

## Уточнение пользователя от 20 ноября

Пользователь выбрал симуляционные данные для разработки. Рабочий демонстрационный сценарий — условные преподаватели, два периода наблюдения, синтетические score и level из скрытого фактора. У каждого сотрудника стабильный SIM-идентификатор; группы не пересекаются между выборками. Код генератора, происхождение и точная конфигурация сохраняются в проекте.

Программная реализация продолжается на этой симуляции. Пункт исходного задания о реальных данных и запрете случайной генерации для исследования при этом не закрыт; данные и метрики явно помечены synthetic / development_demo_only. Приложение и отчёт не должны называть их реальными оценками сотрудников.
