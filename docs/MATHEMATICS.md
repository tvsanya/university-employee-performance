# Математическое описание демонстрационного эксперимента

## Наблюдение и цель

Одна строка относится к условному преподавателю и периоду. У одного преподавателя два наблюдения, поэтому разбиение производится по employee_id. Случайный скрытый фактор генератора создаёт шумные признаки и искусственный score; пороги 55 и 80 превращают его в три класса. Это определение симуляции, а не нормативная методика оценки сотрудника.

efficiency_level является целью; efficiency_score и ID/период/происхождение не являются входами. По существующему контракту используются девять числовых и два категориальных признака. После кодирования на данном train получается 16 входов.

## Преобразование признаков

Для числового столбца пропуск заменяется медианой train. Полностью пустой столбец получает нулевую подстановку. Затем z_j = (x_j - mu_j) / s_j, где mu и s оцениваются только на train; нулевая дисперсия даёт масштаб 1. Категории кодируются one-hot по словарю train; неизвестная категория не создаёт новую колонку, а даёт нули соответствующего блока. Пропуски категорий имеют отдельное значение.

Validation и test не участвуют в оценке статистик. Преобразования и порядок колонок включены в сохраняемую модель, поэтому новый CSV может не содержать цель и связанные исключённые колонки.

## Базовые классификаторы

Константная модель выбирает наиболее частый класс train. Она показывает результат, доступный без зависимости от признаков.

Логистическая модель вычисляет линейные значения a_k = w_k^T z + b_k и softmax p_k = exp(a_k) / sum_j exp(a_j). В бинарном варианте используется один логистический выход. Обучение использует кросс-энтропию, L2-регуляризацию и сбалансированные веса классов. Параметры библиотеки фиксируются в коде и версиях окружения; C = 1 в текущем baseline.

## Глубокая MLP

Для скрытого слоя h_l = activation(W_l h_(l-1) + b_l), h_0 = z. В выбранной сети два скрытых слоя 32 и 16 с ReLU, затем три softmax-выхода. Всего (16*32+32) + (32*16+16) + (16*3+3) = 1123 параметра.

Обучение выполняет Adam по мини-пакетам. Функция содержит взвешенную кросс-энтропию и добавку L2 для матриц весов; нормировка регуляризации соответствует реализации MLPClassifier закреплённой версии. Сбалансированный вес примера класса k равен n / (K*n_k), где частоты вычисляются только по train. Веса и смещения проверяются на конечность после каждой эпохи.

Одна эпоха выполняется через partial_fit. Встроенное случайное early_stopping отключено: validation уже независимо разделена по сотрудникам. После эпохи измеряются train/validation macro-F1, сохраняется лучший checkpoint. Patience ограничивает число эпох без улучшения более min_delta. Test в функцию обучения не передаётся.

## Метрики и выбор

Accuracy = число верных прогнозов / число наблюдений. Для класса k: F1_k = 2*TP_k / (2*TP_k + FP_k + FN_k). Macro-F1 усредняет классы с одинаковым весом; при нулевом знаменателе вклад равен нулю. Набор классов train фиксируется для всех моделей и выборок, а неожиданный класс цели при оценке также не отбрасывается. Отсутствующий в конкретной части класс train не исчезает из среднего.

Сначала выбирается эпоха и конфигурация DL по validation, затем по той же validation сравниваются семейства. При равенстве DL предпочитает меньшую сеть, сравнение семейств сохраняет первый вариант. Test используется для отчёта после выбора. В текущей симуляции линейная модель немного лучше на validation; более высокий test нейросети не меняет решение.

Матрица ошибок содержит истинные классы по строкам и прогнозы по столбцам. Категориальные срезы имеют минимальный размер 20. Они описывают наблюдения и не доказывают причинность, справедливость или пригодность для кадровых решений.

## Воспроизводимость и ограничения

Сохраняются seed, контракт, версии, контрольные суммы исходного CSV/выборок/моделей, параметры и история. JSON-применение реализует те же преобразования и функции выходов без выполнения сериализованных Python-объектов; равенство проверено программно.

Запуск notebooks/research.ipynb обучает обе семьи заново и формирует отчёт/графики. Скрипт scripts/execute_notebook.py выполняет его проектным ядром без изменения глобального каталога Jupyter. Симуляция не закрывает требование реальных данных и сама по себе не доказывает требуемую исследовательскую точность.

Первичные описания используемых алгоритмов: [MLPClassifier](https://scikit-learn.org/stable/modules/generated/sklearn.neural_network.MLPClassifier.html), [LogisticRegression](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html).

## Перестановочная важность

На validation вычисляется исходная метрика s. Для каждого исходного признака j выполняются R независимых перестановок его значений между строками; важность равна среднему s − s_jr. Отрицательные значения сохраняются. Выборочная стандартная девиация повторов описывает случайность перестановок, а не доверительный интервал обобщения. Корреляция признаков и повторные наблюдения ограничивают интерпретацию. Test не используется, модель не переобучается. Источник метода: https://scikit-learn.org/stable/modules/permutation_importance.html .

## Вероятности

Log-loss — среднее −ln p истинного класса с явно записанным ограничением снизу 1e−15. Multiclass Brier здесь определён как средняя по строкам сумма квадратов ошибок по всем классам (диапазон 0–2), без деления на число классов. Top-label ECE — взвешенный модуль различия средней максимальной вероятности и доли верных прогнозов в равных интервалах уверенности. Пустые интервалы сохраняются, условная Accuracy пустой пороговой подвыборки равна null. Показатели оценивают сохранённую модель, не выполняют её калибровку и не меняют выбор модели. Источник: https://scikit-learn.org/stable/modules/calibration.html .

## Устойчивость

Проверяются независимые сценарии: случайные пропуски 5/15/30% ячеек признаков, числовой шум с σ=0.05/0.15/0.30 от сохранённого train-масштаба и полное отсутствие одного признака. Записываются изменение macro-F1, доля сменившихся прогнозов и среднее L1 между векторами вероятностей. Цели, ID и test не изменяются. Проверка чувствительности не является доказательством причинности и не меняет параметры модели.

## Групповой bootstrap

При наличии group_column единицей ресэмплирования служит целая группа сотрудника со всеми его периодами. Из G групп выбираются G с возвращением; метрики фиксированной модели рассчитываются на объединённых строках с сохранением повторов групп и фиксированным набором классов. 95% percentile-интервал берётся по квантилям 0.025/0.975. Учитывается число повторов без отдельных классов. Без group_column единицей служит строка, что требует отдельного предположения независимости. Интервалы не включают повторное обучение и не гарантируют переносимость на реальных сотрудников.

## Распределения признаков

Для числовых признаков сравниваются эмпирические CDF: KS = max |F_train−F_validation|. PSI = Σ(q−p) ln(q/p), границы интервалов определяются только квантилями train, к каждому счётчику добавляется 0.5 перед нормировкой. Категориальное TV = 0.5 Σ |q−p|, отдельно считаются новые категории и пропуски. Цель и идентификаторы исключены контрактом; p-value и универсальный порог опасности не назначаются. Эти расстояния не являются оценкой ошибки модели.
